# CPU

Verilog HDLで記述した、32ビットのパイプラインCPUです。RISC-Vの命令形式を用い、命令の実行、レジスタやメモリへのアクセス、パイプラインで発生するハザードへの対処を実装しています。

## 主な構成

- **5段パイプライン**：命令フェッチ（IF）、デコード（ID）、実行（EX）、メモリアクセス（MA）、書き戻し（WB）。
- **レジスタファイル**：32ビット × 32本。`x0`の読み出し値は常に0です。
- **命令メモリ・データメモリ**：それぞれ32ビット × 64ワード（256バイト）。
- **ALU**：加算、減算、ビット単位のXOR・OR・ANDと、不一致による分岐条件の判定。
- **分岐予測**：gshareで分岐するかどうかを予測し、BTBに保存した分岐先アドレスを使って命令フェッチを進めます。
- **ハザード対策**：演算結果のフォワーディング、ロード直後の依存命令に対するストール、分岐予測が外れたときの後続命令の無効化。
- **結果の観測**：トップモジュールからVIOに32ビットのCPU出力を接続し、Nexys A7の16個のLEDに結果の下位16ビットを表示します。

## 構成と動作

主要モジュールは`scr/m_proc9_F.v`で接続しています。P1〜P4は、IF・ID・EX・MA・WBの5段をつなぐパイプラインレジスタです。

### CPUのデータパス

ロード・ストアのアドレスはALUで計算します。ストア値は`w_in3`から`P3_in3`を経由してデータメモリへ渡します。フォワーディングは、対応する書き込み先レジスタが一致するときに有効になり、P3の演算結果をP4の書き戻しデータより優先します。

### 分岐とパイプライン制御

分岐先はID段で計算してP2に保存し、分岐するかどうかはEX段で判定します。gshareとBTBを用いて次のPCを予測し、予測が外れたときは正しいPCに戻して後続命令を無効化します。

`w_lduse`は、P3段のロード先レジスタとP2段で使うレジスタの依存を検出します。検出中はPC・P1とP2の命令情報を保持し、P2のオペランドを転送値に更新しながら、P3へ無効な命令（バブル）を送ります。コードでは、このストール中はPC更新とP1・P2の分岐無効化処理を保留します。

#### gshare：分岐するかどうかの予測（`scr/m_gshare.v`）

過去の分岐結果を使って、次の分岐が成立するかどうかを予測するモジュールです。5ビットの分岐履歴レジスタ`r_bhr`と、32エントリの2ビット飽和カウンタ`mem`を持ちます。読み出しアドレス`w_radr`と`r_bhr`の排他的論理和（XOR）でカウンタを選び、その上位ビットを予測結果`w_pred`として出力します。

| カウンタ値 | 予測 |
| --- | --- |
| `00` | 強く「分岐しない」 |
| `01` | 弱く「分岐しない」（初期値） |
| `10` | 弱く「分岐する」 |
| `11` | 強く「分岐する」 |

`w_we`が1のクロック立ち上がりで、`w_wadr XOR r_bhr`に対応するカウンタを更新します。実際の分岐結果`w_tkn`が1なら加算、0なら減算し、値は0〜3の範囲に保ちます。同時に、履歴を`{w_tkn, r_bhr[4:1]}`に更新して最新の結果を最上位ビットへ入れます。履歴の初期値は0です。

#### BTB：分岐先アドレスの記憶（`scr/m_btb.v`）

BTB（Branch Target Buffer）は、分岐命令のPCと分岐先アドレスを対応づけて保存するモジュールです。32エントリを持ち、各エントリは有効ビット1ビット、タグ25ビット、分岐先アドレス32ビットの合計58ビットで構成します。

現在のPC`w_pc[6:2]`でエントリを選び、有効ビットが1で、タグが`w_pc[31:7]`と一致すると`w_hit`を1にします。保存した分岐先は`w_dout`に出力します。`w_we`が1のクロック立ち上がりで、`w_wadr`のエントリへ`w_wd`を書き込みます。全エントリの初期値は0で、起動直後は無効です。同じエントリを使う別のPCを登録すると、以前の内容は置き換わります。

#### CPU本体との連携

`scr/m_proc9_F.v`では、gshareの読み出しに`r_pc[6:2]`、BTBの検索に`r_pc`を使います。gshareが「分岐する」と予測し、かつBTBがヒットした場合に、BTBの分岐先`w_ppc`を次のPC候補にします。それ以外は`PC + 4`へ進みます。

EX段に有効な分岐命令があるとき（`P2_v & P2_b`）、gshareへ実際の分岐結果を渡し、BTBへ`{1'b1, P2_pc[31:7], P2_tpc}`を書き込みます。BTBの登録は、分岐が成立しなかった場合にも行います。

分岐結果から求めた正しい次のPC`w_truepc`と、後続命令のPC`P1_pc`が異なり、両命令が有効な場合に`w_miss`を1にします。PCの選択は、誤予測の修正、予測した分岐先、`PC + 4`の順で優先します。ロード依存によるストール中はPCを保持します。

現在の実装では、gshareの更新にその時点の履歴を使い、予測時の履歴やカウンタの位置をパイプラインに保存していません。また、両モジュールの更新条件にはストールの除外がないため、P2に有効な分岐命令が保持されている間もクロックごとに更新します。

### 計算結果からLEDまで

`x30`への有効な書き戻しをCPUの出力に保存し、`scr/m_main.v`でLEDとVIOに接続します。

## ファイル構成

Verilogソース（`.v`）は`scr/`にまとめています。`asm.vh`はリポジトリ直下、テストベンチは`tests/`にあります。Vivadoでは`scr/`内のソースを追加し、リポジトリ直下をインクルード検索先に設定してください。

| ファイル | 役割 |
| --- | --- |
| `scr/m_main.v` | トップモジュール。CPU、VIO、16ビットのLED出力を接続 |
| `scr/m_proc9_F.v` | CPU本体。パイプライン制御と各モジュールの接続 |
| `scr/m_gshare.v` | 5ビットの分岐履歴と32個の2ビット飽和カウンタによる分岐方向の予測 |
| `scr/m_btb.v` | 32エントリの分岐先アドレス保存と、PCのタグ照合によるヒット判定 |
| `scr/m_RF2.v` | レジスタファイルと書き込みデータのバイパス |
| `scr/m_alu.v` | 算術・論理演算と分岐条件の判定 |
| `scr/m_adder.v` | PC更新や分岐先計算に使う32ビット加算器 |
| `scr/m_mux.v` | 32ビットの2入力マルチプレクサ |
| `scr/m_get_type.v` | オペコードに基づく命令形式の判定 |
| `scr/m_get_imm.v` | 命令からの即値生成 |
| `scr/m_gen_imm.v` | 命令形式の判定と即値生成をまとめ、ロード命令を識別 |

## サンプルプログラム

`asm.vh`には、`addi`、`add`、`bne`を使って0から100までを加算するプログラムが記述されています。意図する処理は次のとおりです。

```text
x10 = 0
x3 = 0
x1 = 101

繰り返し:
    x10 = x10 + x3
    x3 = x3 + 1
    x3 != x1 なら繰り返しに戻る

x30 = x10
```

計算結果は **5050（0x000013BA）** です。Icarus Verilogのシミュレーションで、LED出力が`16'h13BA`になり、プログラムの再実行中も表示が維持されることを確認しています。実機での表示と100 MHz動作のタイミング検証は未実施です。

末尾の`HALT`というコメントは、`addi x30, x10, 0`を終了の目印として使うことを表しています。`scr/m_RF2.v`は`x30`への書き込み時に`$finish`を呼び出してシミュレーションを終了します。

プログラムを変更する場合は、`asm.vh`の各`MM`要素に格納する命令語を編集します。

## 動作確認の準備

### CPU単体のシミュレーション

`m_proc9_F`を呼び出してクロックを供給するテストベンチを用意し、CPU本体と依存する各`.v`ファイルを読み込みます。`asm.vh`はインクルードファイルとして参照できるようにしてください。CPU単体の確認では、VIOを参照する`scr/m_main.v`は不要です。

### LED出力のシミュレーション

Icarus Verilogを使用する場合は、このフォルダーで次を実行します。実行ファイルのパスはインストール先に合わせてください。

```powershell
$cpuSources = (Get-ChildItem -Path scr -File -Filter *.v).FullName
$ledSimPath = Join-Path $env:TEMP 'cpu_led.vvp'
& C:\iverilog\bin\iverilog.exe -g2012 -DSYNTHESIS -s tb_main_led -I . -o $ledSimPath tests/tb_main_led.sv $cpuSources
if ($LASTEXITCODE -eq 0) { & C:\iverilog\bin\vvp.exe $ledSimPath }
```

`SYNTHESIS`を定義すると、レジスタファイルの自動終了処理が無効になり、テストベンチがLED出力を確認してから終了します。このテストには観測用のVIOスタブが含まれます。`tests`配下のファイルはFPGAの合成対象に追加しないでください。

テストでは初期消灯、5050の表示と再実行時の保持、ロードした32ビット値の下位16ビット表示、結果0での全消灯、全ビット1での全点灯を確認します。

### FPGAでの利用

Nexys A7-100Tでは、`m_main`をトップモジュールとして使用し、`nexys_a7.xdc`をVivadoのConstraintsに追加します。このファイルは提供されたNexys A7-100Tの汎用XDCを基に、100 MHzクロックと16個のLEDの行を有効にしたものです。`m_main`の入出力はXDCと同じ名前で、クロックが`CLK100MHZ`、LED出力が`LED[15:0]`です。その他の周辺機器の設定はコメントとして残しています。

既存のXDCに`w_clk`や旧1ビット出力`r_out`の制約がある場合は、このファイルの割り当てに置き換えてください。

別途、`clk`と32ビットの`probe_in0`を持つ`vio_0`のIPが必要です。VIOのIPとFPGAプロジェクトはこのリポジトリに含まれていません。

`LED[0]`をLD0、`LED[15]`をLD15に接続します。Nexys A7のLEDは1で点灯、0で消灯します。[Digilent公式マニュアル](https://digilent.com/reference/_media/reference/programmable-logic/nexys-a7/nexys-a7_rm.pdf)

5050を表示するときのビット列は、LD15からLD0の順で次のようになります。

```text
0001 0011 1011 1010
```

点灯するLEDは **LD12、LD9、LD8、LD7、LD5、LD4、LD3、LD1** です。表示するのは下位16ビットなので、65535を超える値は上位ビットが省略されます。電源投入時の出力は0で、CPUが`x30`へ結果を書き戻した後に更新されます。

`$finish`はシミュレーション終了用で、合成時は除外します。実機ではCPUは動作を続け、表示値は次の`x30`書き込みまで保持されます。

## 現在の実装範囲

命令のデコードと制御は限定的です。たとえば、ALUの演算選択は主に`funct3`に依存し、分岐条件は不一致判定です。また、U形式・J形式の即値生成はありますが、それだけで対応する命令全体の実行を保証するものではありません。RISC-V命令セットへの完全準拠は確認していません。

CPUには外部リセット入力がなく、レジスタやメモリの初期化には宣言時の初期値や`initial`ブロックを使っています。
