# CPU

Verilog HDLで記述した、32ビットのパイプラインCPUです。RISC-Vの命令形式を用い、命令の実行、レジスタやメモリへのアクセス、パイプラインで発生するハザードへの対処を実装しています。

## 主な構成

- **5段パイプライン**：命令フェッチ（IF）、デコード（ID）、実行（EX）、メモリアクセス（MA）、書き戻し（WB）。
- **レジスタファイル**：32ビット × 32本。`x0`の読み出し値は常に0です。
- **命令メモリ・データメモリ**：それぞれ32ビット × 64ワード（256バイト）。
- **ALU**：加算、減算、ビット単位のANDと、不一致による分岐条件の判定。
- **ハザード対策**：演算結果のフォワーディング、ロード直後の依存命令に対するストール、分岐成立時の後続命令の無効化。
- **結果の観測**：トップモジュールからVIOに32ビットのCPU出力を接続し、Nexys A7の16個のLEDに結果の下位16ビットを表示します。

## サンプルプログラム

`asm.vh`には、`addi`、`add`、`bne`を使って0から100までを加算するプログラムが記述されています。意図する処理は次のとおりです。

```text
x10 = 0
x3 = 0
x1 = 101

繰り返し:
    x10 = x10 + x3
    x3 = x3 + 1
    x3 != x1 なら繰り返しに戻る

x30 = x10
```

計算結果は **5050（0x000013BA）** です。Icarus Verilogのシミュレーションで、LED出力が`16'h13BA`になり、プログラムの再実行中も表示が維持されることを確認しています。実機での表示と100 MHz動作のタイミング検証は未実施です。

末尾の`HALT`というコメントは、`addi x30, x10, 0`を終了の目印として使うことを表しています。`m_RF2.v`は`x30`への書き込み時に`$finish`を呼び出してシミュレーションを終了します。

プログラムを変更する場合は、`asm.vh`の各`MM`要素に格納する命令語を編集します。

## 動作確認の準備

### CPU単体のシミュレーション

`m_proc9_F`を呼び出してクロックを供給するテストベンチを用意し、CPU本体と依存する各`.v`ファイルを読み込みます。`asm.vh`はインクルードファイルとして参照できるようにしてください。CPU単体の確認では、VIOを参照する`m_main.v`は不要です。

### LED出力のシミュレーション

Icarus Verilogを使用する場合は、このフォルダーで次を実行します。実行ファイルのパスはインストール先に合わせてください。

```powershell
$cpuSources = (Get-ChildItem -File *.v).FullName
$ledSimPath = Join-Path $env:TEMP 'cpu_led.vvp'
& C:\iverilog\bin\iverilog.exe -g2012 -DSYNTHESIS -s tb_main_led -I . -o $ledSimPath tests/tb_main_led.sv $cpuSources
if ($LASTEXITCODE -eq 0) { & C:\iverilog\bin\vvp.exe $ledSimPath }
```

`SYNTHESIS`を定義すると、レジスタファイルの自動終了処理が無効になり、テストベンチがLED出力を確認してから終了します。このテストには観測用のVIOスタブが含まれます。`tests`配下のファイルはFPGAの合成対象に追加しないでください。

テストでは初期消灯、5050の表示と再実行時の保持、ロードした32ビット値の下位16ビット表示、結果0での全消灯、全ビット1での全点灯を確認します。

### FPGAでの利用

Nexys A7-100Tでは、`m_main`をトップモジュールとして使用し、`nexys_a7.xdc`をVivadoのConstraintsに追加します。このファイルは提供されたNexys A7-100Tの汎用XDCを基に、100 MHzクロックと16個のLEDの行を有効にしたものです。`m_main`の入出力はXDCと同じ名前で、クロックが`CLK100MHZ`、LED出力が`LED[15:0]`です。その他の周辺機器の設定はコメントとして残しています。

既存のXDCに`w_clk`や旧1ビット出力`r_out`の制約がある場合は、このファイルの割り当てに置き換えてください。

別途、`clk`と32ビットの`probe_in0`を持つ`vio_0`のIPが必要です。VIOのIPとFPGAプロジェクトはこのリポジトリに含まれていません。

`LED[0]`をLD0、`LED[15]`をLD15に接続します。Nexys A7のLEDは1で点灯、0で消灯します。[Digilent公式マニュアル](https://digilent.com/reference/_media/reference/programmable-logic/nexys-a7/nexys-a7_rm.pdf)

5050を表示するときのビット列は、LD15からLD0の順で次のようになります。

```text
0001 0011 1011 1010
```

点灯するLEDは **LD12、LD9、LD8、LD7、LD5、LD4、LD3、LD1** です。表示するのは下位16ビットなので、65535を超える値は上位ビットが省略されます。電源投入時の出力は0で、CPUが`x30`へ結果を書き戻した後に更新されます。

`$finish`はシミュレーション終了用で、合成時は除外します。実機ではCPUは動作を続け、表示値は次の`x30`書き込みまで保持されます。

## 現在の実装範囲

命令のデコードと制御は限定的です。たとえば、ALUの演算選択は主に`funct3`に依存し、分岐条件は不一致判定です。また、U形式・J形式の即値生成はありますが、それだけで対応する命令全体の実行を保証するものではありません。RISC-V命令セットへの完全準拠は確認していません。

CPUには外部リセット入力がなく、レジスタやメモリの初期化には宣言時の初期値や`initial`ブロックを使っています。
